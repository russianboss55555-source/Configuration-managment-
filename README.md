# Эмулятор оболочки ОС

Практическая работа № 1 по дисциплине «Конфигурационное управление».

**Вариант 22 · Силаев Егор Игоревич · ИКБО-18-25**

Эмулятор на Python с графическим REPL: ввод команды, разбор аргументов,
выполнение и вывод результата. Файлы и каталоги образуют виртуальную файловую
систему (VFS) в памяти. Исходный ZIP используется только для чтения.

Репозиторий: [Configuration-managment-](https://github.com/russianboss55555-source/Configuration-managment-).

## Что реализовано

1. **REPL.** Окно Tkinter, имя VFS в заголовке, ввод по Enter и кнопке,
   раскрытие переменных окружения, заглушки `ls` и `cd`, команда `exit`.
2. **Конфигурация.** Аргументы запуска и их отладочный вывод, стартовый
   сценарий с отображением диалога и продолжением после ошибок.
3. **VFS.** Загрузка ZIP в дерево в памяти, Base64 для файлов, ошибки
   загрузки и три генерируемых тестовых набора.
4. **Основные команды.** Заглушки заменены командами `ls` и `cd`;
   добавлены `tac`, `cal`, `du`.
5. **Дополнительная команда.** `touch` создаёт файлы и обновляет метки
   в памяти. Для изменений ZIP на диске не открывается.

## Запуск и настройки

Требуется **Python 3.10 или новее**. Для окна нужен Tkinter, наличие
которого можно проверить командой `python -m tkinter`. Пакеты через
`pip` и отдельная сборка не нужны. Команды ниже запускаются из корня проекта.

```powershell
# Windows: демонстрация полной версии в окне
.\demo\run-nested.bat

# Windows: пустая VFS
.\run.bat

# Windows: свой ZIP и стартовый сценарий
python -m src.main --vfs "my files.zip" --script "start.txt"
```

В Linux/macOS: `sh run.sh` или `sh demo/run.sh nested`.
Готовый пример автоматически генерирует архив перед запуском.

| Параметр | Назначение |
| --- | --- |
| `--vfs ПУТЬ` | ZIP на диске. Без него создаётся пустая VFS `memory`. |
| `--script ПУТЬ` | UTF-8 сценарий, выполняемый при старте. Допускается BOM. |
| `--headless` | Вывод в терминал без окна. Требует `--script`. |
| `--help` | Справка по запуску. |

Значения параметров выводятся в начале сеанса. Имя VFS совпадает с именем
архива. Ошибка загрузки ZIP завершает запуск с кодом 1. При ошибке чтения
скрипта GUI остаётся доступным, а в текстовом режиме возвращается код 1.

## Команды

| Синтаксис | Результат |
| --- | --- |
| `ls [-al] [--] [путь]` | Список имён. `-a` включает скрытые, `-l` показывает тип, размер в байтах и время изменения в UTC. |
| `cd [--] [каталог]` | Переход в каталог. Вызов без аргументов возвращает в корень VFS. |
| `tac [--] файл [файл ...]` | Строки каждого UTF-8 файла в обратном порядке с их разделителями. |
| `cal [год \| месяц год]` | Календарь текущего месяца, заданного года или месяца. Неделя начинается с понедельника. |
| `du [-ash] [--] [путь]` | Объём исходных данных. `-a` включает файлы, `-s` оставляет итог, `-h` форматирует единицы. |
| `touch [-c] [--] путь [путь ...]` | Создаёт пустой файл или обновляет время доступа и изменения. `-c` пропускает создание файла. |
| `exit` | Завершение приложения. Аргументы запрещены. |

Виртуальные пути используют `/`: абсолютный путь начинается с `/`,
относительный отсчитывается от текущего каталога, `.` и `..` обозначают
текущий и родительский каталоги. В `ls` и `du` по умолчанию используется
текущий каталог. Короткие флаги можно объединять, например `ls -al`.
После `--` аргументы воспринимаются как пути, даже если начинаются с дефиса.

`du` складывает несжатые размеры файлов, включая скрытые. Без `-h`
значения выводятся в байтах. В режиме `-h` 1 KiB = 1024 B.
`-a` и `-s` взаимоисключающие. `tac` сообщает об ошибке для каталога,
двоичного файла или пути, которого нет в VFS. `touch` требует
существующий родительский каталог. Для существующего каталога он
обновляет метки, для существующего файла также сохраняет содержимое.

Двойные кавычки сохраняют пробелы в одном аргументе и разрешают подстановки
`$NAME` и `${NAME}`. Одинарные кавычки сохраняют текст буквально.
Значения берутся из окружения реальной ОС, остаются одним аргументом
и повторно не раскрываются. Неизвестная переменная и незакрытая кавычка
дают сообщение об ошибке. Парсер реализует учебное подмножество оболочки:
конвейеры, перенаправления и запуск системных команд отсутствуют.

Стартовый скрипт обрабатывается построчно. Пустые строки и строки,
начинающиеся с `#` после пробелов, пропускаются. Ошибочная команда
показывается в диалоге, следующая строка выполняется. Корректная `exit`
прерывает сценарий и закрывает приложение.

## Демонстрация

| Скрипт Windows | Что проверяет |
| --- | --- |
| `demo\run-minimal.bat` | Пустой ZIP с корнем и сценарий этапов 1–3. |
| `demo\run-multiple.bat` | Несколько файлов, скрытый и двоичный файл, пустой каталог. |
| `demo\run-nested.bat` | Три уровня каталогов и сценарий команды `touch`. |

В Linux/macOS доступны те же наборы через
`sh demo/run.sh minimal`, `sh demo/run.sh multiple` и `sh demo/run.sh nested`.
Для режима без окна добавьте `--headless`.

Сценарии лежат в `examples/startup/`: `config.txt` для конфигурации,
`stage3.txt` для загрузки VFS и базового диалога, `stage4.txt`
для команд чтения, `stage5.txt` для `touch`, `exit.txt` для остановки.
Каждый сценарий с командами содержит и успешные примеры, и ошибки;
`exit.txt` отдельно проверяет, что строка после выхода не выполняется.

```powershell
# Все наборы; ZIP создаются в examples/generated
python -m examples.make_vfs all

# Все режимы команд чтения (этап 4) с выводом в терминал
.\demo\run-nested.bat --script examples/startup/stage4.txt --headless

# Проверка остановки после exit
.\run.bat --script examples/startup/exit.txt --headless

# Ошибки VFS: отсутствующий путь и неверный формат
.\run.bat --vfs missing.zip
.\run.bat --vfs README.md
```

Для ручной проверки запустите `demo\run-nested.bat` и введите в окне:

```text
ls -al /
cd "/my documents"
tac plan.txt
cd /docs
touch "контроль.txt"
ls -l
du -ah .
cd /отсутствует
cal 11 2026
exit
```

Откройте тот же ZIP повторно: файлы, созданные в предыдущем сеансе,
исчезнут. Это проверяет, что `touch` изменил только дерево в памяти.

## Структура и тестирование

| Файл | Назначение |
| --- | --- |
| `src/main.py`, `src/config.py` | `main`, `launch_gui`, `parse_args` и `Config.describe`: запуск, разбор параметров, выбор окна или текстового режима. |
| `src/gui.py`, `src/startup.py` | `TerminalWindow`: окно, история и приглашение. `read_script`, `run_script`, `execute_line`: чтение сценария и общий цикл диалога. |
| `src/parser.py` | `parse_command`, `decode_fragment`, `expand_variables`: разбор слов, кавычек и окружения. |
| `src/shell.py` | `Shell.execute` передаёт команду обработчику, `Shell.prompt` показывает текущий путь, `CommandResult` хранит ответ и признак выхода. |
| `src/commands.py` | Разбор флагов и путей, вывод `ls`, чтение `tac`, календарь, подсчёт `du`, обработка путей `touch`. |
| `src/vfs.py` | `load_zip` проверяет и загружает записи, `resolve` проходит дерево, `touch` меняет узлы, `VirtualFile` кодирует и декодирует байты. |
| `examples/`, `demo/` | Генерация архивов, сценарии команд и запуск демонстраций. |
| `tests/` | Автоматические проверки парсера, скриптов, VFS и команд. |

```powershell
python -m unittest discover -s tests -v
```

Проверки охватывают разбор путей и переменных, продолжение сценария после
ошибки, загрузку трёх ZIP, неверный формат архива, ошибки команд, размеры
исходных данных и сохранность ZIP после `touch`. Тесты логики работают
без графического дисплея. Для проверки окна используется ручной сценарий.

Этапы отражены в истории Git отдельными коммитами `feat(repl)`,
`feat(config)`, `feat(vfs)`, `feat(commands)` и `feat(touch)`.
В репозитории хранятся исходники, скрипты и документация; тестовые ZIP,
кеш Python и настройки IDE исключены через `.gitignore`.
